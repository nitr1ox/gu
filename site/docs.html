Documentation de l'API

API REST serveur-à-serveur pour créer des panels et piloter l'ajout de membres sauvegardés, leur planification et les statistiques, depuis un autre bot ou un script.

Vue d'ensemble

  • URL de base : https://ton-domaine.com/v1
  • Format : JSON en entrée et en sortie (Content-Type: application/json pour les requêtes avec corps).
  • Taille maximale d'un corps : 10 Ko.
  • Cache : les réponses ne sont jamais mises en cache (Cache-Control: no-store).
  • Identifiants Discord : user_id, guildId et source sont des IDs Discord de 17 à 20 chiffres (sauf source = "all").

Authentification

Chaque requête doit contenir l'en-tête :

Authorization: Bearer <clé>

Clé client (serveur)

Définie par l'hébergeur dans la variable d'environnement API_KEYS, au format nom:secret, séparées par des virgules :

API_KEYS=monbot1:secret1,monbot2:secret2
  • Le nom (a-z A-Z 0-9 _ -, 32 caractères max) identifie le client. Sans nom, la clé est nommée key1, key2, etc.
  • Le client agit pour plusieurs utilisateurs : user_id est obligatoire à chaque appel (ID Discord de la personne qui a lancé la commande dans l'autre bot).
  • Cloisonnement : un panel créé par une clé n'est ensuite accessible que par cette même clé (sinon 403).
  • Migration : API_LEGACY_CLIENT=nom fait adopter par ce client les anciens panels créés avant le cloisonnement.

Le secret est comparé via son empreinte SHA-256 ; il n'est jamais stocké en clair.

Clé personnelle

Créée par un utilisateur dans le panel (5 clés maximum par compte). Elle commence par ak_.

  • Elle n'agit que pour son propriétaire.
  • user_id est facultatif ; s'il est fourni, il doit correspondre au propriétaire (sinon 403).
  • Aucun panel n'est créé par POST /panels : le panel existe déjà.
  • Elle fonctionne même si API_KEYS est vide.

Panels

POST /panels

Crée le panel d'un utilisateur, ou le retrouve s'il existe déjà (idempotent).

ChampTypeObligatoireDescription
user_idstringoui (clé client)ID Discord de l'utilisateur
usernamestringnonNom affiché dans le journal d'audit (64 car. max)

201 si le panel vient d'être créé, 200 sinon :

{
  "created": true,
  "panel_url": "https://ton-domaine.com/panel/",
  "redirect_uri": "https://ton-domaine.com/callback",
  "has_bot": false,
  "bots": [],
  "totals": { "bots": 0, "saved_members": 0 }
}

redirect_uri est l'URL à ajouter dans l'onglet OAuth2 de l'application Discord de l'utilisateur.

GET /panels/:userId

Renvoie les bots, serveurs et statistiques d'un utilisateur.

{
  "panel_url": "https://ton-domaine.com/panel/",
  "bots": [
    {
      "id": "123456789012345678",
      "name": "MonBot",
      "online": true,
      "invite_url": "https://discord.com/oauth2/authorize?client_id=...",
      "saved_members": 2000,
      "guilds": [
        { "id": "987654321098765432", "name": "Mon serveur", "configured": true, "saved_members": 1284 }
      ]
    }
  ],
  "totals": { "bots": 1, "saved_members": 2000 }
}
  • guilds est limité à 50 serveurs par bot.
  • configured vaut true quand le rôle « Vérifié » est choisi pour ce serveur.
  • 404 si l'utilisateur n'a pas de panel (clé client).

Serveurs

Pour tous les appels de cette section, l'utilisateur doit être propriétaire ou administrateur du serveur et avoir un de ses bots dedans. Sinon : 404 « Serveur introuvable, ou tu n'y es pas admin avec un de tes bots. »

GET /guilds/:guildId/stats?user_id=...

{
  "guild": { "id": "987654321098765432", "name": "Mon serveur", "member_count": 2100 },
  "bot": { "id": "123456789012345678", "name": "MonBot" },
  "configured": true,
  "saved_members": 1284,
  "bot_total_saved_members": 2000,
  "restoring": false
}
  • saved_members : membres sauvegardés pour ce serveur.
  • bot_total_saved_members : membres sauvegardés par ce bot, tous serveurs confondus.
  • restoring : true si une restauration est en cours sur ce serveur.

Ajout de membres (restauration)

Les jetons des membres appartiennent à l'application du bot qui les a collectés : le serveur cible doit contenir le même bot que le serveur source.

POST /guilds/:guildId/members/add

Lance immédiatement l'ajout des membres sauvegardés dans le serveur guildId (cible).

ChampTypeObligatoireDescription
user_idstringoui (clé client)ID Discord de l'utilisateur
sourcestringouiID du serveur d'origine, ou "all"

202 :

{ "job_id": "abc123" }
CodeMessage
400La source doit être un autre serveur.
400Ce serveur utilisait un autre bot : invite ce même bot ici pour restaurer.
403Tu n'as pas configuré le bot sur ce serveur source.
409Une restauration est déjà en cours.
  • Une seule restauration à la fois par serveur cible.
  • Environ 1,1 seconde par membre (limites de débit Discord) : ~18 minutes pour 1 000 membres.
  • À partir de 50 membres (ALERT_MASS_RESTORE), une alerte est envoyée au serveur.
  • Les membres qui ont retiré l'application ne peuvent plus être ajoutés et sont supprimés de la base.

GET /jobs/:jobId?user_id=...

Progression d'un ajout de membres (seul l'utilisateur qui l'a lancé peut le consulter).

{ "status": "running", "total": 1284, "done": 600, "added": 540, "already": 40, "failed": 20 }
ChampDescription
statusrunning, done ou error
totalNombre de membres à traiter
doneNombre de membres déjà traités
addedMembres ajoutés au serveur
alreadyMembres déjà présents
failedÉchecs (jeton expiré/révoqué, refus de Discord…)

404 « Introuvable. » si le job n'existe pas ou n'appartient pas à l'utilisateur.

Planification

POST /guilds/:guildId/members/schedule

ChampTypeObligatoireDescription
user_idstringoui (clé client)ID Discord de l'utilisateur
sourcestringouiID du serveur d'origine, ou "all"
run_atnumber/stringouiHeure d'exécution

Formats de run_at : timestamp en millisecondes ou en secondes (nombre ou chaîne), ou date ISO 8601 avec fuseau (2026-12-01T20:00:00+01:00 ou ...Z). Une date sans fuseau est refusée.

Contraintes : au moins 1 minute dans le futur, au plus 30 jours ; au moins un membre sauvegardé dans la source ; 5 planifications en attente max par serveur (MAX_SCHEDULES_PER_GUILD, 429 au-delà) ; mêmes contrôles qu'un lancement immédiat, refaits à l'heure prévue.

201 :

{ "schedule_id": "xyz789", "run_at": 1796151600000, "expected": 1284 }

Si le serveur est éteint à l'heure prévue, la planification n'est pas exécutée en retard au-delà de 10 minutes (SCHEDULE_GRACE_MINUTES) : elle passe en statut missed.

GET /guilds/:guildId/members/schedules?user_id=...

Liste les 10 dernières planifications du serveur.

{
  "schedules": [
    {
      "id": "xyz789",
      "source": "111111111111111111",
      "source_name": "Ancien serveur",
      "expected": 1284,
      "run_at": 1796151600000,
      "status": "pending",
      "by": "pseudo",
      "job_id": null,
      "error": null
    }
  ]
}
StatutSignification
pendingEn attente
startedLancée (voir job_id)
failedNon lancée à l'heure prévue (voir error)
missedServeur indisponible à l'heure prévue
cancelledAnnulée

DELETE /guilds/:guildId/members/schedules/:id?user_id=...

Annule une planification en attente.

{ "ok": true }

404 « Planification introuvable. » · 409 si elle n'est plus en attente.

Exemples

Créer un panel (clé client)

curl -X POST https://ton-domaine.com/v1/panels \
  -H "Authorization: Bearer secret1" \
  -H "Content-Type: application/json" \
  -d '{"user_id":"123456789012345678","username":"pseudo"}'

Statistiques d'un serveur (clé personnelle)

curl "https://ton-domaine.com/v1/guilds/987654321098765432/stats" \
  -H "Authorization: Bearer ak_xxxxxxxx..."

Lancer un ajout de membres, puis suivre le job

curl -X POST https://ton-domaine.com/v1/guilds/987654321098765432/members/add \
  -H "Authorization: Bearer secret1" \
  -H "Content-Type: application/json" \
  -d '{"user_id":"123456789012345678","source":"111111111111111111"}'

curl "https://ton-domaine.com/v1/jobs/abc123?user_id=123456789012345678" \
  -H "Authorization: Bearer secret1"

Planifier pour le 1er décembre à 20 h (heure de Paris)

curl -X POST https://ton-domaine.com/v1/guilds/987654321098765432/members/schedule \
  -H "Authorization: Bearer secret1" \
  -H "Content-Type: application/json" \
  -d '{"user_id":"123456789012345678","source":"all","run_at":"2026-12-01T20:00:00+01:00"}'

Node.js

const res = await fetch('https://ton-domaine.com/v1/guilds/987654321098765432/stats?user_id=123456789012345678', {
  headers: { Authorization: 'Bearer secret1' },
});
const data = await res.json();
if (!res.ok) throw new Error(data.error);
console.log(data.saved_members);
